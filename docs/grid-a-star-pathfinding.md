# Grid A* Pathfinding

状态：DAY_18 已完成独立算法原型；尚未接入场景中的敌人移动。

## 输入与移动规则

`Pathfinding` 接收一个包含边界和静态障碍的有限矩形网格。坐标边界包含最小值和最大值，只允许上下左右四方向移动，每步代价为 1。

启发函数采用 Manhattan 距离：

```text
h(n) = |n.x - goal.x| + |n.y - goal.y|
```

在四方向、单位代价规则下，该估计忽略障碍且不会高估真实剩余代价，适合用于本原型的 A* 搜索。

## 搜索状态与返回契约

- `openList` 保存已经发现、等待处理的节点；当前实现以线性扫描选择 `f = g + h` 最小的节点。
- `closedList` 保存本次搜索已经处理完的节点。
- `GCost` 保存从起点到当前节点的实际代价，`HCost` 保存剩余代价估计。
- `Parent` 保存前驱；找到终点后沿前驱回溯，再反转得到从起点到终点的路径。
- 成功时返回 `true`，路径包含起点和终点。
- 起点等于终点时返回只包含该点的零步路径。
- 输入非法或终点不可达时返回 `false`，输出路径为 `null`。

地图障碍与边界是跨搜索保存的配置；open、closed、代价和前驱在每次调用时重新建立，因此同一个寻路器可以重复使用。

## 当前实现成本

设最多处理 `V` 个可走节点。每次从 `List<Node>` 中寻找最低 `f` 最坏需要 `O(V)`，整个搜索最坏约为 `O(V²)`；open、closed 和节点状态占用 `O(V)` 空间。当前网格很小，线性列表实现便于观察和调试。需要扩大地图或提高请求频率时，再评估优先队列和更快的坐标查找结构。

## 运行测试

在 Unity 中打开 `Window > General > Test Runner`，选择 `EditMode` 并运行 `PathfindingTests`。

当前七项测试覆盖：

- 空网格上的最短路径；
- 起点等于终点；
- 直线路径被障碍阻挡后的最短绕行；
- 被阻塞的起点与终点；
- 合法但不可达的终点；
- 越界输入；
- 同一寻路器连续执行失败与成功搜索时不残留旧状态。

DAY_18 的 Test Runner 结果为 7 passed、0 failed；可读性清理后的两个程序集另经 `dotnet build TacticalRoguelite.Pathfinding.Tests.csproj --no-restore` 验证为 0 warning、0 error。
